## 오늘 새로 쓴 명령
git config, git add, git commit, git push

## 왜 이걸 하는지
git 으로 올릴 때는 왜 add · commit · push 세 단계로 나눌까요?
- 한 번에 올리면 올리면 안 되는 파일(.env, 캐시 파일 등)까지 같이 올라가 버려서

## 이 말이 무슨 뜻인지
commit (커밋)
-add로 고른 파일들의 **그 시점의 모습(스냅샷)**을 내 PC의 git 기록에 저장하는 것, 나중에 기록 목록을 봤을 때 "무엇을 왜 바꿨는지" 알아보려고

push (푸시)
-내 PC에 쌓아 둔 **커밋(기록)**을 깃허브의 원격 저장소(origin)로 보내는 것

## 찾아보고 알게 된 것
add 와 commit 과 push 는 파일을 깃허브에 올리는 과정을 세 단계로 나눈 명령이다.
- add: 이번에 올릴 파일을 고르는 단계
- commit: add 로 고른 파일들의 현재 상태를 내 PC 안에 기록으로 남기는 단계
- push: 내 PC 에 쌓아 둔 커밋(기록)을 깃허브(원격 저장소)로 보내는 단계

untracked · tracked · staged 는 git 이 파일을 어떻게 다루고 있는지를 나타내는 상태이다.
- untracked (Untracked files, 빨강): git 이 한 번도 기록한 적 없는 새 파일
- tracked: git 이 기억하고 있는 파일
- staged (Changes to be committed, 초록): git add 로 "다음 커밋에 넣기로 고른" 파일
