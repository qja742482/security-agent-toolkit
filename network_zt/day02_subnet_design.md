## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:
192 11000000
168 10101000
10 00001010
25 00011001
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 10진수 숫자를 앞을 0으로 채운 8자리 2진수 글자로 바뀐다.
  예를 들어 11000000
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답: 1010
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: 그래야 주소가 모두 32비트이다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: IPv4 주소 하나는 32비트인데 점으로 나뉜 마디(옥텟 · octet) 하나는 8비트라, 마디마다 0~255 를 담습니다
- (다-2) 32비트로 만들 수 있는 주소의 개수:
2³² = 4,294,967,296개
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답:비트 한 자리에는 0 또는 1, 즉 2가지 값이 들어가요. 자리가 32개이므로 2를 32번 곱해요(2³²). 2⁸ = 256, 2¹⁶ = 65,536, 2³² = 4,294,967,296 순으로 커진다.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: 43억 개는 전 세계 인터넷 기기 수에 비해 부족해서 주소가 고갈될 수밖에 없었어요. 그래서 집이나 회사 안에서는 192.168.x.x 같은 사설 IP를 쓰고, NAT가 공인 IP 하나를 여러 기기가 나눠 쓰도록 바꿔 주는 방식을 쓰게 됐어요.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP:
IPv4 주소: 192.168.100.185
공인 IP: 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: 모름
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답:공인 IP이다. 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: 172.20.5.6은 내부망 장비,172.32.5.6은 외부 주소이다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: 인터넷으로 나갈 때 NAT 장비(공유기)가 출발지 주소를 공유기의 공인 IP로 바꿔서 내보낸다. 그래서 외부 서버 로그에는 PC의 사설 IP가 아니라 공인 IP만 남고, 같은 공인 IP 뒤에 여러 PC가 있으면 그중 어느 PC인지 알 수 없다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 정적 NAT은 사설 IP 하나와 공인 IP 하나를 항상 1:1로 고정해서 연결한다. 동적 NAT은 공인 IP 여러 개를 모아 둔 풀에서, 통신할 때마다 비어 있는 공인 IP를 임시로 골라 연결한다. 같은 PC도 매번 다른 공인 IP를 받을 수 있다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 사원 PC 수보다 공인 IP가 적고, PC들이 항상 동시에 인터넷을 쓰는 것도 아니어서, 쓰는 순간에만 공인 IP를 빌려 주는 동적 NAT이 효율적이다. 이 환경에서 외부 로그의 공인 IP로 PC를 특정하려면 로그에 찍힌 시각을 NAT 장비의 변환 기록(어떤 사설 IP가 언제 어떤 공인 IP로 바뀌었는지)과 함께 봐야 한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 내부망의 사설 IP 를 인터넷으로 보낼 때 공인 IP 로 바꾸는 주소 변환
  사설 IP 는 인터넷에서 쓸 수 없는 주소라, 그대로 보내면 응답이 돌아올 수 없습니다

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:

## 5교시 · 스위치와 라우터

### 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

- (가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나: 있다

  - 답: ARP 캐시는 같은 망만 저장되는데 8.8.8.8은 다른망이라 프레임의 목적기 MAC을 8.8.8.8이 아닌 게이트웨이의 MAC으로 정해 보내기 때문이다.
- (다-1) MAC 주소와 IP 주소는 각각 누가 정하나요?
  - 답: 스위치와 라우터

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.1 · 6.3

- 부서마다 VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN 에 같은 서브넷을 주었을 때 PC 와 스위치가 각각 어떻게 동작하는지와 견주어 설명하세요.
  - 답: VLAN은 스위치가 포트를 나누는 번호이고 서브넷은 PC가 쓰는 IP 주소 범위라서, 부서마다 둘을 맞춰 두어야 VLAN 10 포트에 꽂힌 개발팀 PC가 192.168.10.x 주소로 같은 망 안에서 통신한다. 서로 다른 VLAN 에 같은 서브넷을 주면 PC는 목적지가 같은 망이라고 판단해 게이트웨이로 보내지 않고 직접 보내려 하고, 스위치는 VLAN 이 달라서 그 프레임을 막는다. 그래서 라우터가 있어도 통신이 되지 않는다. 또 VLAN 번호를 셋째 마디와 같게 맞추면(10 ↔ 192.168.10) 주소만 보고도 어느 부서, 어느 VLAN인지 알 수 있다

### 2. 라우팅 경로 — 6-2

- 운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8` 이 지나는 장비와, 라우터가 그때 쓴 라우팅 표의 줄: 운영팀 PC → 스위치(VLAN 20) → 운영팀 게이트웨이 192.168.20.1(라우터) → 인터넷 쪽 라우터 → 8.8.8.8 순서로 지난다. 8.8.8.8 은 회사 망 세 줄에 맞지 않으므로 라우터는 기본 경로 줄 0.0.0.0/0(다음 홉: 인터넷 쪽 라우터)을 쓴다.
- 라우터가 6-2 의 `192.168.30.5`(보안팀 PC)와 이 통신(`8.8.8.8`)에서 다음 홉을 다르게 고른 이유를, 라우팅 표에서 맞는 줄을 찾는 순서로 설명하세요.
  - 답: 라우터는 회사 망 세 줄을 위에서부터 하나씩 확인하고, 하나도 맞지 않으면 기본 경로로 보낸다. 192.168.30.5 는 셋째 줄 192.168.30.0/24 에 들어가서 그 줄의 다음 홉인 직접 연결 VLAN 30 으로 보낸다. 8.8.8.8 은 첫째 마디부터 회사 망과 달라 세 줄 어디에도 맞지 않으므로, 마지막으로 기본 경로 0.0.0.0/0 줄을 골라 인터넷 쪽 라우터로 보낸다.

### 3. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유:
 같은 망이면 스위치로 직접, 다른 망이면 게이트웨이로 보내는 판단이 중요하다고 생각한다.
 그 이유는 로그에서 처음 보는 주소가 나와도 마스크로 망 부분을 비교하면 내부 통신인지 외부 통신인지 바로 구별할 수 있기 때문이다.
