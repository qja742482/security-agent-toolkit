## 3교시 · 승인과 반려

### 문제 3-1 · 승인 · 반려 함수 만들고, 두 번째 처리가 막히는지 확인하기

- (가) 실행한 출력 전체를 붙여 넣고, 막힌 세 줄이 각각 왜 막혔는지 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 막힌 세 줄 각각의 이유
  - 답:

1. 
```
--- 단계 1: 처리 - 본인 요청 시험 한 건, 승인 · 반려 여섯 건을 처리한다
1 본인 승인 -> True 승인
1 승인 -> False 검토 중이 아님
2 반려 -> True 반려
3 승인 -> True 승인
4 승인 -> True 승인
1 승인 -> False 검토 중이 아님
2 승인 -> False 검토 중이 아님
--- 단계 2: 점검 - 요청서 목록
1 seoyeon approved approver
2 gaeun approved approver
3 dami approved approver
4 junho approved approver
```
2. 
1 승인 -> False 검토 중이 아님 - 1번 요청은 바로 위 줄에서 승인되어서
1 승인 -> False 검토 중이 아님 - 1번 요청을 또 승인하려고 해서
2 승인 -> False 검토 중이 아님 - 2번 요청은 앞에서 반려로 처리가 되어서

- (나) 🔍 이미 승인한 요청서를 다시 승인하지 못하게 막는 이유는 무엇인가요? 막지 않으면 어떤 일이 생길 수 있나요?
  - 쓸 내용: ① 막는 이유 ② 막지 않을 때 생길 수 있는 일
  - 답:
  1. 요청서는 검토 중 -> 승인 또는 반려로 딱 한 번만 처리되는 흐름인데 이미 처리된 요청서를 다시 처리하면 이 흐름이 깨지기 때문이다
  2. 중복이 승인된다, 반려를 뒤집을 수 있다, 만료 시각을 몰래 조작할 수 있다.

- (다) 🔍 `approve_request` 에서 `request["user"] == approver` 검사를 뺀다면 어떤 위험이 생길까요? 요청자가 친구에게 대신 승인해 달라고 부탁하면 이 검사로는 막을 수 없습니다. 이런 경우를 막으려면 무엇이 더 필요할까요?
  - 쓸 내용: ① 검사를 뺐을 때의 위험 ② 더 필요한 장치 한 가지 이상
  - 답:
  1. 이 검사는 요청자 본인이 자기 요청을 승인하지 못하게 막는 장치인데 이걸 빼면 요청자가 직접 요청서를 쓰고 직접 승인할 수 있게 된다.
  2. 승인 권한자 목록 제한, 승인 기록 남기기, 승인 사유 작성 요구
